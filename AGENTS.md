# Project Agent Guide

## Source of Truth

- Treat `package.json`, `astro.config.mjs`, and the source tree as
  authoritative. They take precedence over README prose.
- Keep this file focused on project-specific constraints and workflows. Link to
  source files rather than duplicating dependency versions, full schemas, or
  exhaustive route lists.

## Architecture

- This is an Astro static site hosted on Cloudflare Pages. The project uses Bun,
  Tailwind CSS 4, Basecoat, MDX, and a small React/React Flow island.
- `src/pages/` owns file-based routes. Most site pages are Astro; collection
  detail pages use static `getStaticPaths()` routes.
- `src/layouts/Layout.astro` is the global shell. It owns page metadata,
  canonical URLs, global styles, the sidebar and mobile shell, theme handling,
  search mounting, analytics, and View Transition lifecycle behavior.
- `src/navigation.ts` is the source of truth for sidebar items, nesting, active
  matching, icons, and collapsible homelab sections. Update it when a routed
  page should appear in the sidebar.
- `src/styles/global.css` imports Tailwind and Basecoat. Keep page- or
  component-specific styling colocated unless it is a reusable global rule.
- `public/` holds files served verbatim. Reference them with root-relative URLs
  such as `/avatar.webp`; do not import them as application modules.

## Content and Routes

- `src/content.config.ts` defines the `posts` and `projects` collections. Keep
  collection schemas on `astro/zod`; Astro's collection API requires it.
- Posts live under `src/content/posts/`; projects live under
  `src/content/projects/`. Read the schema before changing frontmatter.
- Collection entry IDs are public slugs. Renaming or moving a content file can
  change its URL. Preserve IDs unless redirects and all relevant links are
  handled deliberately.
- Post and project detail routes render collection entries with `render()`.
  Posts derive reading time from the collection body. Do not replace this with a
  different content representation without an approved migration plan.
- Post pagination is centralized in `src/posts.ts`. Page 1 is `/posts/`; later
  pages are `/posts/page/<n>/`. Do not duplicate pagination logic in routes.
- Homelab documentation is independent page-routed MDX in `src/pages/homelab/`,
  using `src/layouts/HomelabPage.astro`. New homelab pages need valid local
  frontmatter, including `currentPage`, and may need a navigation entry.
- Photography, uses, newsletter, and the 404 page are normal static pages, not
  collection-backed CMS content.

## Interactive Code

- Prefer Astro components. React is intentionally isolated to the homelab
  canvas; do not introduce React for ordinary static UI without a concrete need.
- The homelab topology belongs in `src/data/homelab-canvas.ts`. Keep
  `HomelabCanvas.tsx` and `HomelabNode.tsx` focused on rendering the static,
  read-only React Flow graph rather than duplicating topology data.
- `Layout.astro` enables Astro ClientRouter/View Transitions. Body content can
  swap without a full page reload. Client behavior must follow the existing
  `astro:page-load` lifecycle and cleanup/reinitialization patterns.
- Do not replace Basecoat reinitialization, theme-class transfer, mobile scroll
  locking, or sidebar/popover cleanup in `Layout.astro` casually. These guard
  against duplicate listeners and stale DOM references after navigation.
- For new interactive behavior, preserve keyboard support, focus behavior,
  visible focus states, and existing theme behavior. Browser-test interactions
  across a ClientRouter navigation, not only after a hard refresh.

## Search and External Browser Integrations

- Pagefind indexes the built static site. Its runtime files are generated by
  `bun run build`, so search is not meaningful from a clean checkout running
  only `bun run dev`.
- `src/components/search.astro` lazy-loads `/pagefind/pagefind.js`. Preserve the
  Pagefind external-resolution plugin in `astro.config.mjs`; Vite must not try
  to bundle that generated file.
- The newsletter's browser validation uses Valibot. Turnstile verification and
  the subscription service are external contracts; this repository has no
  newsletter backend.
- Everything sent to browser code is public. Never add credentials, private API
  keys, or privileged tokens to Astro client scripts, public assets, or
  frontmatter.

## Validation

Start with the narrowest relevant check:

| Change type | Required evidence |
| --- | --- |
| Astro, TypeScript, routes, or content types | `bun run typecheck` |
| Targeted source change | `bunx biome lint <path>` |
| Routes, content, config, Pagefind, assets, or deployment behavior | `bun run build` |
| Layout, theme, sidebar, search, form, or View Transition changes | Browser smoke test of the affected behavior and a client-side navigation |

- There is no repository CI workflow; local verification is required before
  deployment.
- `bun run check` currently reports diagnostics in generated
  `worker-configuration.d.ts`. Do not edit that generated file to silence
  diagnostics; use the focused checks above until the lint configuration is
  corrected.

## Dependencies and Generated Files

- Use Bun for dependency changes and commit the corresponding `bun.lock` update.
- Do not manually edit `dist/`, `.astro/`, or `.wrangler/`; they are generated
  build or local-state directories.
- `.agents/` and `.claude/` are local workspaces and must not be committed.

## Deployment Safety

- Production is the Git-integrated Cloudflare Pages project `v3frankie-me` on
  the `main` branch. Pushes to `main` are the normal deployment path.
- `bun run cfdeploy` is manual recovery only. It builds the site and uploads
  `dist` to Pages.
- Do **not** substitute `wrangler deploy`: it targets a Worker, while this site
  is hosted on Pages. Using it can deploy only one side of the site and leave
  cached HTML referencing missing hashed CSS/JS assets.
- Docker is not the production deployment path. Do not change the hosting model,
  publish directory, or static output mode without explicit approval.
- After a production deployment that affects assets or the site shell, verify a
  page HTML response and its referenced `/_astro/*` asset both return `200`.

## Maintaining This Guide

Update this file when deployment commands, output targets, routing conventions,
content architecture, or ClientRouter lifecycle behavior changes. Remove
workarounds once their underlying issue is resolved.
